# BUMP TEST_FAILURE sweep — finding semantic (production-forcing) breaks

Goal: expand the catalog of *known behavioural breaks* (like xstream 1.4.18) by sweeping
BUMP's entire `TEST_FAILURE` corpus, not just the 9 we hand-picked. Generated by
`scripts/nadia_scripts/bump_semantic_sweep.py` over `data/benchmark_test_failures/` +
`_merged/` (205 entries), classifying each by the dominant exception in its reproduction log.

## Corpus breakdown (205 entries)

| kind | count | what it is | useful? |
|---|---:|---|---|
| `missing_class` | 77 | ClassNotFoundException / NoClassDefFoundError — relocation, jakarta namespace, classpath | ✗ syntactic |
| `syntactic` | 43 | NoSuchMethod/Field/AbstractMethodError, InvalidClassException — API/serial break | ✗ compile-level |
| `test_assertion` | 30 | AssertionError / ComparisonFailure — output changed, adapted in tests | ✗ test-level |
| `binding_init` | 21 | ClassCast / ExceptionInInitializer at logger/provider init (slf4j-style) | ✗ config, not code |
| `jvm_version` | 11 | UnsupportedClassVersionError — library needs newer Java (BUMP ran Java 11) | ✗ artifact |
| **`semantic`** | **14 (+6 `semantic?`)** | **runtime exception thrown from the library's own logic on a production path** | ✅ **this is what we want** |
| other | 3 | | — |

## Key finding

**BUMP's TEST_FAILURE corpus is ~90% NON-semantic.** The overwhelming majority are
compile/classpath/namespace/JVM/test-assertion breaks — not production-forcing behavioural
breaks. Only ~20 entries (≈8 distinct breaks after dedup) are the xstream-style semantic
kind, and several of those are single-project or niche. So **BUMP is a broad but
low-semantic-yield source** — the same lesson we hit mining slf4j/logback/httpclient/jsoup.
The clean semantic gems (xstream default-deny, POI byte-cap) mostly came from EXTERNAL
signature-mining, not BUMP wholesale — indeed BUMP has only **1** xstream entry, and its
POI entries are the crypt-class relocation (`missing_class`), a *different* POI break than
the verifiable byte-cap.

## The semantic shortlist (distinct breaks, ranked by mine-ability)

Best = a library that got STRICTER and now throws on input/data it used to accept, in a
production call path (the xstream property). Full data: `output/bump_semantic_shortlist.json`.

| rank | library | transition | exception | why it's promising | caveat |
|---|---|---|---|---|---|
| 1 | **net.minidev:json-smart** | 2.4.8 → 2.4.9 | `ParseException` | stricter JSON parser throws on previously-accepted input; parsing is production code — clean xstream analogue | only 1 project (btrplace) |
| 2 | **org.json:json** | 20090211 → 20230227 | `JSONException` | stricter parsing over a huge version jump; production JSON handling | huge span; pick a tighter boundary |
| 3 | **com.h2database:h2** | 1.3.175 → 2.0.206 | `SqlException` | major SQL-compat behaviour change; throws at runtime on real queries | Hibernate-mediated; adaptation often SQL/schema, sometimes test DB |

## Recommendation

1. **Promote the top 3–4 as new catalog breaks** (`json-smart`, `org.json:json`, `h2`,
   maybe `commons-io`) — add `bump_breaks_catalog.json` entries with the boundary + an
   external-mining signature (the parser/behaviour method the client calls), then mine
   real client adaptations the way we did for xstream. The parser-strictness ones (1,2) are
   the cleanest analogues.
2. **Don't rely on BUMP alone for breadth** — at ~10% semantic yield it gives only a
   handful of new seeds. Complement with a CURATED list of known "default-flip" security/
   strictness breaks that force production adaptations (the richest vein):
   - xstream 1.4.18 default-deny ✅ (done)
   - POI 5.0 byte-cap ✅ (done)
   - **SnakeYAML 2.0** SafeConstructor default (no arbitrary object construction)
   - **Jackson** default-typing PTV (weaker — opt-in; see jackson-ptv-mimic caveat)
   - json-smart / org.json parser strictness (from this sweep)
   - Log4j2 2.15+ JNDI/lookup disabling, commons-configuration interpolation changes
3. **Feed all of these to the automation agent** (direction #1) so each break's many client
   candidates are processed without hand-work — that's where scale comes from
   (dataset ≈ #breaks × #verifiable-adaptations-per-break).
